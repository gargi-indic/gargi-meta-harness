## 2. Campaigns = registered repos (one campaign per repo in M2)
- Campaign id = the repo full name `owner/repo`. Routes use two path params: `/api/campaigns/{owner}/{repo}/graph`. Unknown repo (not in `config.repos`) → 404 `{"detail": "unknown campaign"}`.
- `GET /api/campaigns` → `list[CampaignSummary]` for every repo in `config.repos` (order as in config): `{id, repo, control_issue: int|null (from parse_repo_config(get_repo(...)["config_json"]) or RepoConfig()), title: repo, counts: {ready, running, needs_you, review, blocked, done, failed}}` (all ints, zero when nothing is cached).
- Issue set for a campaign = `list_issues(store, repo)` minus the control issue.
- `status_of(issue, open_blockers, labels)` in derive.py, first match wins: label `harness:failed` → failed; issue closed → done; label `harness:done` → done; `harness:needs-you` → needs-you; `harness:review` → review; `harness:running` → running; `harness:blocked` → blocked; open blockers non-empty → blocked; else ready.
- `agent` = value of an `agent:<x>` label, else the repo config's `default_agent`; `playbook` = `playbook:<y>` label else `default_playbook`. `run_id` = latest run for the issue (`latest_runs_by_issue`) if its status is not terminal, else null. `url` = `https://github.com/{repo}/issues/{number}`.
- `GET /api/campaigns/{owner}/{repo}/graph` → `{nodes: [GraphNode], edges: [{source, target}]}`; nodes sorted by number; one edge per `blocked_by` link blocker → blocked, only when both are in the node set, sorted by (source, target).

## 3. Board
`GET /api/board?campaign=owner/repo` (optional; omitted = all registered repos) → `{columns: {ready, running, needs_you, review, blocked, done, failed}}` (a `failed` column is added to the issue's list). `Card = {repo, issue, title, agent, playbook, run_id|null, pr: int|null (latest run's context.pr.number), blocked_by: [int] (all links, not only open), updated_at}`; cards in each column sorted by `updated_at` desc then issue. Unknown campaign → 404.

## 4. Inbox
`GET /api/inbox` → `list[InboxItem]` sorted by `created_at` then id. One item per step with `status == "waiting"` and truthy `output.needs_you`, in runs whose status is not terminal. Fields:
- `id` = step id; `run_id`, `step_id`, `repo`, `issue`, `title` (cached issue title or `#<n>`), `summary` (`output.reason` or ""), `agent` (`run.context.get("agent")`), `created_at` (`step.started_at` or run.updated_at), `gate_id` (`output.gate_id` or null).
- `kind` (a plain `str` in the schema, documented values): gate node with `gate == "plan"` → `plan_approval`; `gate == "merge"` → `merge_approval`; other gate names → `gate`; escalate node → `question` when the most recent other `done` step of the run (by `ended_at`, then id) has outcome `needs_input`, else `escalation`; any other node kind → the node kind. Node kind comes from the run's playbook (§1 facts); unknown node → `escalation`.
- `pr`: null unless `run.context["pr"]` has an int number: `{number, url: context.pr.url or https://github.com/{repo}/pull/{n}, checks: [...]}` where checks = for each `check` node, its latest step: `{name: node_id, state: outcome or status}`, followed by each `{name: f["name"], state: f["conclusion"]}` of a failed ci step's `output.failed`.
- `findings`: from the run's latest `review` step output `findings` (list of `{severity, file, problem, required_change}`) → `[{severity, text: "<file>: <problem>" or problem}]`; [] if none.
Resolved items disappear automatically (step no longer waiting).

## 5. Runs and activity
- `GET /api/runs?status=&issue=&repo=` → `list[RunSummary]` = `{id, repo, issue, title, playbook_id, status, agent, pr: int|null, current_node: str|null (node of the latest non-done step, else null), created_at, updated_at}`, newest first. Filters optional; `status` must be one of `RUN_STATUSES` else 422.
- `GET /api/runs/{id}` → `{run: RunSummary, playbook: dict (run.context["playbook"], else builtin_playbooks()[run.playbook_id].model_dump(mode="json"), else null), steps: [{id, node, visit, status, outcome, ref, started_at, finished_at}], visit_counts: {node: max visit}}`; steps ordered by (started_at, visit, id). Do NOT return `run.context` wholesale (it can hold large outputs). Unknown → 404 `{"detail": "unknown run"}`.
- `GET /api/runs/{id}/activity?after=0&limit=200` (`limit` 1..500, else 422) → `{items: [{seq: event id, ts: data.ts or row ts, step_id: data.step, kind, text}], next: <last seq returned, or `after` when empty>}`. `kind` mapping from the adapter's kind: `message|agent|user` → message, `tool|command|bash` → tool, `state|status|plan|progress|end` → state (the Jules adapter emits progress, message, plan, end), anything else → note. Text already redacted at write time; redact again on read (cheap, defensive). Unknown run → 404.

## 6. SSE event types (events.py)
Constants `EVT_RUN_UPDATED="run.updated"`, `EVT_STEP_UPDATED="step.updated"`, `EVT_ACTIVITY="activity"`, `EVT_INBOX_CHANGED="inbox.changed"`, `EVT_ISSUE_UPDATED="issue.updated"`, `EVT_LOG="log"`, documented in the module docstring. `KIND_TO_TYPES: dict[str, tuple[str, ...]]`:
- `run_started`, every `run_*`, `paused`, `resumed`, `retry`, `cancel_error` → (run.updated, issue.updated) (`run_needs-you`, `run_done`, `run_failed`, `run_cancelled` also add inbox.changed)
- `step_waiting`, `step_done` → (step.updated, inbox.changed); `executor_error`, `exhausted`, `no_route`, `unknown_node`, `routing_loop` → (step.updated,)
- `needs_you` → (inbox.changed, step.updated)
- `agent_activity` → (activity,)
- anything else → (log,)
`EventLogTailer.poll_once` publishes one bus event per mapped type per row (same payload as today: `{id, ts, repo, issue, run_id, kind, data}`), in row order. Keep #23's redaction and exactly-once semantics; update its tests for the new types.
