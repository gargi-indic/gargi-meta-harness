BINDING spec for #40 (M3.7 parallel/join). The maintainer accepted the issue's default design (decision recorded on #1 and #40):
- one step per (node, visit) as today; a `parallel` node completes with outcome `fork`; the runner then schedules every target of that port's edge list as independent steps in the same run (several `running` steps allowed);
- a `join` node has a step per visit that stays `waiting` until its arrival condition is met, counting arrivals from distinct incoming source steps of the current fork id (`fork_id` stored in step output as `f"{run_id}/{step_id}"`).
Follow the issue body (scratchpad issue40.md) exactly for scope/acceptance criteria, plus:

Read first: docs/PLAN.md ("Playbook schema", "Engine semantics"), docs/LESSONS.md, harness/playbook/ (models + validator + JSON schema export), harness/engine/runner.py, harness/engine/executors/ (registry + base: Done/Waiting), harness/engine/model.py, the existing runner/engine tests. Reuse; do not reinvent. Existing runner and engine tests must pass UNMODIFIED (single-token behaviour byte-compatible).
2. Playbook models: `parallel.fork` edge may be a list of targets; `join` has `mode: all|any|select` and optional `inputs: [..]`, ports `done` and `failed`. 4. Executors `harness/engine/executors/parallel.py` and `join.py`, registered in the executor registry. Parallel: Done("fork", {"fork_id": ..., "targets": [...]}). Join `all`: Waiting until every input branch step of this fork is terminal; all done -> Done("done", {"branches": {node: outcome}}); any failed/exhausted -> Done("failed") and cancel still-running siblings. Join `any`: Done("done") as soon as one branch reaches the join with a success outcome, output records `winner`, siblings cancelled. Template access `{{ join.branches.<node> }}` / `{{ join.winner }}` through the existing output-templating contract.
