2. Event-kind mapping (row.kind -> notification):

   - the budget events #56 records (grep harness for the exact event-log kinds, expected `budget_warning`/`budget_exceeded`; if #56 is not merged yet, match any kind starting with `budget` and say so in the PR) -> kind `budget`.

   Everything else is ignored. Default enabled kinds: plan_approval, merge_approval, gate, question, escalation, handoff, budget.
3. Idempotency across processes and restarts: dedupe key = `<kind>:<run_id>:<event row id>` for event-driven ones and `notify:<step id>` for the notify executor. Before sending, record the key GitHub-first-irrelevant but durable locally: `set_meta`/`get_meta` (harness/store/repo.py:420-425) under `notified:<key>` (INSERT-if-absent semantics: check then set; send only if absent). So a restart or a second process (daemon + serve) never re-sends. Local-only is acceptable here because a notification is an ephemeral local effect, not run state; say so in the PR. Additionally dedupe in memory by (kind, issue) inside `dedupe_window` (default 60s) and coalesce bursts: more than 3 notifications within 10s become ONE `N items need you` notification (injectable clock; the coalescing flush must be deterministic in tests, no real sleeps).
